# PWA: install and offline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The site installs as an app on tablets and desktop and works offline, each film included once it has been played.

**Architecture:** A hand-written TypeScript service worker (`src/pwa/sw.ts`) built as an extra Rollup entry into an unhashed `dist/sw.js`; a build plugin writes the precache list and a content hash into it. Pure logic (routing, Range slicing, ETag decision, precache list) lives in testable modules; the worker only wires them to the Cache API. The Worker (`worker/index.ts`) does not change.

**Tech Stack:** Vite 8, TypeScript, React 19, vitest (node environment), Cache API / Service Worker, ImageMagick (`convert`) for the icons.

**Spec:** `docs/superpowers/specs/2026-10-22-pwa-design.md`. One simplification against it: there is no separate `page` cache; `index.html` is in the precached `app-*` cache and navigations are network-first with that copy as the fallback.

## Global Constraints

- Films stay at `/videos/*` on the same origin; the Worker is unchanged.
- No new dependencies (no Workbox, no vite-plugin-pwa).
- The repo is public: no secrets, tokens or account ids.
- The service worker is registered in production builds only (`import.meta.env.PROD`).
- A film is cached after its first play, not up front. Tablets and desktop only.
- Cache names: `app-<build hash>` (older `app-*` deleted on activate) and `films-v1` (never dropped by a deploy).
- Interface strings are written with `t('español', 'English')` (`src/i18n.ts`).
- Commit messages are `type: subject`; commit small, **do not push**; `npm test` and `npm run typecheck` pass before each commit.
- Do not run `npm run deploy`. Use `npm run deploy:dry` at most.
- Windows is case-insensitive: no two files whose names differ only in case.

## Review Focus

- `bytes=0-` and `bytes=0-1` (what Safari sends first) on a cached film answer 206 with the right `Content-Range`. (Task 1)
- A range starting past the end answers 416 with `Content-Range: bytes */<size>`; a multi-range or malformed header answers the whole film with 200. (Task 1)
- Two requests for the same uncached film start one background download; a download that fails (offline, quota) is swallowed and leaves no half entry. (Task 3)
- Opening `/?lang=en` offline shows the page: navigation falls back to the cached `index.html` whatever the query. (Task 3, checked in Task 6)
- A file name with `|`, a quote or a backslash makes the build fail loudly instead of corrupting the precache list. (Task 2)

### Task 1: Service-worker logic (pure)

**Files:**
- Create: `src/pwa/swLogic.ts`
- Test: `src/pwa/swLogic.test.ts`

**Interfaces:**
- Consumes: `rangeBounds`, `contentRange`, type `R2Range` from `worker/range.ts`.
- Produces:
  - `type Route = 'film' | 'page' | 'app' | 'ignore'`
  - `routeOf(url: URL, request: { method: string; mode: string }, origin: string): Route`. `ignore` for another origin or a method other than GET; `film` for a path matching `/videos/<name>.mp4`; `page` for `mode === 'navigate'`; `app` otherwise.
  - `parseRange(header: string | null): R2Range | null`. Handles `bytes=a-b`, `bytes=a-`, `bytes=-n`; null for no header, a multi-range, or bad syntax.
  - `partialResponse(body: Blob, rangeHeader: string | null, type?: string): Response`. No usable range: 200 with the whole body. Range inside the body: 206 with `Content-Range`. Start at or past the end: 416 with `Content-Range: bytes */<size>`. Always sets `Accept-Ranges: bytes`, `Content-Length` and `Content-Type` (default `video/mp4`).
  - `filmChanged(storedEtag: string | null, currentEtag: string | null): boolean`. True only when `currentEtag` is non-null and differs from `storedEtag`.

- [ ] **Step 1: Write the failing tests** in `swLogic.test.ts` (node environment; `Blob`, `Response`, `URL` exist in Node):
  - `routeOf`: `https://x/videos/natera.mp4` GET → `film`; same URL with `POST` → `ignore`; `https://other/videos/natera.mp4` → `ignore`; `https://x/?lang=en` with `mode: 'navigate'` → `page`; `https://x/assets/index-abc.js` → `app`; `https://x/videos/natera.en.vtt` → `app`.
  - `parseRange`: `'bytes=0-'` → `{ offset: 0 }`; `'bytes=0-1'` → `{ offset: 0, length: 2 }`; `'bytes=-500'` → `{ suffix: 500 }`; `null`, `'bytes=0-1,5-9'`, `'items=0-1'`, `'bytes=a-b'` → `null`.
  - `partialResponse` on a 1000-byte Blob: no header → status 200, `content-length` `1000`; `'bytes=0-'` → 206, `content-range` `bytes 0-999/1000`; `'bytes=0-1'` → 206, `bytes 0-1/1000`, body length 2; `'bytes=-10'` → `bytes 990-999/1000`; `'bytes=2000-'` → 416, `content-range` `bytes */1000`; `'bytes=0-1,5-9'` → 200 whole body; every case has `accept-ranges: bytes`; body bytes of a 206 equal the slice (build the Blob from a `Uint8Array` of 0..255 repeating).
  - `filmChanged`: `('"a"', '"a"')` false; `('"a"', '"b"')` true; `('"a"', null)` false; `(null, '"b"')` true.

### Task 2: Precache list and build plugin

**Files:**
- Create: `src/pwa/precachePlugin.ts`
- Test: `src/pwa/precachePlugin.test.ts`

**Interfaces:**
- Consumes: `Plugin` type from `vite`; `node:fs`, `node:path`, `node:crypto`.
- Produces:
  - `listPrecache(dir: string): string[]`: every file under `dir` as a sorted relative POSIX path, except `sw.js`, `_headers`, and `videos/*.mp4`. Throws `Error` naming the file if a path contains `|`, `'`, `"` or `\`.
  - `buildHash(dir: string, files: string[]): string`: first 12 hex chars of a sha256 over each file's name and bytes, in list order.
  - `injectManifest(code: string, files: string[], hash: string): string`: replaces the literal `__PRECACHE_FILES__` with `files.join('|')` and `__BUILD_HASH__` with `hash`; throws if either token is absent.
  - `precachePlugin(): Plugin`: `apply: 'build'`, `writeBundle` reads `<outDir>/sw.js`, rewrites it with the three functions above, writes it back.

- [ ] **Step 1: Write the failing tests** using a temp dir (`fs.mkdtempSync(path.join(os.tmpdir(), 'precache-'))`) holding `index.html`, `assets/a-1.js`, `models/f.glb`, `videos/natera.mp4`, `videos/natera.jpg`, `videos/natera.en.vtt`, `sw.js`, `_headers`:
  - `listPrecache` returns exactly `['assets/a-1.js','index.html','models/f.glb','videos/natera.en.vtt','videos/natera.jpg']`.
  - A file named `we|ird.txt` makes `listPrecache` throw with the name in the message.
  - `buildHash` is 12 hex chars, stable across two calls, and different after one file's bytes change.
  - `injectManifest("const F='__PRECACHE_FILES__',B='__BUILD_HASH__'", ['a','b'], 'h1')` returns `"const F='a|b',B='h1'"`; a code string without the tokens throws.
- [ ] **Step 2:** Run `npx vitest run src/pwa/precachePlugin.test.ts`. Expected: FAIL.
- [ ] **Step 3:** Implement the four exports in `src/pwa/precachePlugin.ts`.
- [ ] **Step 4:** Run it. Expected: PASS.

### Task 3: The service worker and its registration

**Files:**
- Create: `src/pwa/sw.ts`, `src/pwa/register.ts`
- Modify: `vite.config.ts`, `src/main.tsx`, `tsconfig.json` only if the worker types need it
- Test: build check (no unit test; the logic is in Tasks 1 and 2)

**Interfaces:**
- Consumes: Task 1 (`routeOf`, `partialResponse`, `filmChanged`), Task 2 (`precachePlugin`).
- Produces: `dist/sw.js` (classic script, no `import`/`export`), and `registerServiceWorker(): void` in `register.ts`.

- [ ] **Step 1: `sw.ts`.** Two constants the plugin rewrites: `const FILES = '__PRECACHE_FILES__'`, `const BUILD = '__BUILD_HASH__'`; the file list is `FILES.split('|')` filtered for empty. Type `self` as `ServiceWorkerGlobalScope` (`/// <reference lib="webworker" />`, or a minimal local interface if the lib clashes with `DOM`). Behaviour:
  - `install`: open `app-<BUILD>`, add `index.html` and each listed file (URLs resolved against `self.registration.scope`) with `new Request(url, { cache: 'reload' })`; then `skipWaiting()`.
  - `activate`: delete every `app-*` cache except the current one; `clients.claim()`.
  - `fetch`: `routeOf(...)`; `ignore` → return without `respondWith`.
    - `app`: cache-first from `app-<BUILD>` (`ignoreSearch: true`), else network.
    - `page`: network-first; on failure answer the cached `index.html` whatever the query.
    - `film`: open `films-v1`; if stored, answer `partialResponse(await stored.blob(), request.headers.get('range'))` and `waitUntil` a revalidation (below); if not stored, `waitUntil` `cacheFilm(url)` and answer `fetch(request)`.
  - `cacheFilm(url)`: one in flight per URL (a `Set`); `fetch(url, { cache: 'reload' })` **without** `Range`; store only a `200` whose body fully arrives; swallow every error (offline, quota) and leave no entry.
  - Revalidation: `fetch(url, { method: 'HEAD', cache: 'no-store' })`; if `filmChanged(stored.headers.get('etag'), response.headers.get('etag'))`, delete the entry and `cacheFilm(url)`; ignore a failed HEAD.
- [ ] **Step 2: `register.ts`.** `registerServiceWorker()` does nothing unless `import.meta.env.PROD` and `'serviceWorker' in navigator`; on `window` `load` it registers `new URL('sw.js', document.baseURI)`; a registration error is logged with `console.warn` and otherwise ignored. Call it from `src/main.tsx` after `createRoot(...).render(...)`.
- [ ] **Step 3: `vite.config.ts`.** Add `precachePlugin()` to `plugins`; add `build.rollupOptions.input = { index: 'index.html', sw: 'src/pwa/sw.ts' }` and `output.entryFileNames = (chunk) => chunk.name === 'sw' ? 'sw.js' : 'assets/[name]-[hash].js'`. If Vite refuses a non-HTML entry beside `index.html`, or hoists shared code into a chunk `sw.js` would import, build the worker with a second `build()` call (IIFE, one file) inside the plugin instead.
- [ ] **Step 4: Verify.** Run `npm run typecheck && npm run build`. Expected: both succeed. Then `grep -c "__PRECACHE_FILES__\|__BUILD_HASH__" dist/sw.js` → `0` (tokens replaced), `grep -cE "^(import|export) " dist/sw.js` → `0`, and `grep -o "models/floor_baked.glb" dist/sw.js` finds the entry while `grep -c "videos/natera.mp4" dist/sw.js` → `0`.
- [ ] **Step 5:** `npm test`. Expected: pass. Commit `feat: service worker with offline app and film cache`.
