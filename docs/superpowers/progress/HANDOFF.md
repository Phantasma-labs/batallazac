## How to drive and verify in the browser pane

- `.claude/launch.json` at the repo root (`app-dev`, port 5173, runs `npm --prefix app run dev`). If the server is down use `preview_start` name `app-dev`; if the user's own server holds 5173, `navigate` to `http://localhost:5173`.
- The pane is hidden, so requestAnimationFrame does not run. Take a small screenshot to force the first paint, wait for the loader (**the models take about 30 s to decode**), then drive frames: `window.__drive = async (m, n = 120) => { const k = window.__map; k.clock.seek(m); for (let i = 0; i < n; i++) { await new Promise(r => setTimeout(r, 16)); k.advance(performance.now()); } }` (minutes after midnight: 630 = 10:30, 1020 = 17:00). `window.__map` appears a moment after the scene shows. A screenshot is 800 px wide **and shows the state one step behind: take two**.
- Close-ups: use `?cam=free` and set `__map.camera.position` / `__map.controls.target` (then `advance`); `__map.three()` is the R3F state (`scene`, `raycaster`, `gl`). A canvas `toDataURL()` right after `advance` can be shown in an `<img>` overlay to see a transient frame.
- Gotchas: **Windows is case-insensitive, so two files whose names differ only in case collide** (`pins.ts` / `Pins.tsx`, `troops.ts` / `Troops.tsx`, `shadowSync.ts` / `ShadowSync.tsx` all did, hence `places.ts`, `troopModels.ts`, `shadowDirty.ts`): name the data module differently from the component. After renaming files Vite keeps a stale module for the old name: use a new name or restart the dev server. After several quick edits to one file Vite may serve a half-edited copy ("does not provide an export named ..."): `touch` the file and reload. `seek()` re-enables the camera director; with zoom on, set `window.__map.bus.directorOn = false` after three frames to hold a wide shot. Edits with backslashes through the shell can arrive mangled: use the editor tool for those.
- Blind-key files from the critic rounds lived in the session scratchpad and are gone; the verdicts above are already decoded.
